# Food Demand Analysis

## المشكلة
الشركة تعاني من هدر مواد في بعض المراكز ونفاد وجبات في أخرى، وتريد فهم الطلب والعروض والخصومات وتذبذب الوجبات.

## أهم 3 نتائج أولية
- إجمالي الطلبات في بيانات التدريب: **119,557,485** عبر الأسابيع 1–145.
- الفئة الأعلى طلبًا: **Beverages** بنسبة **33.9%**.
- ارتباط الخصم بالطلب ضعيف موجب: **Spearman ρ=0.122**؛ لا يثبت السببية.

## هيكل المشروع
- `data/raw/`: ملفات المصدر؛ لا تعدّلها ولا ترفعها إلى GitHub.
- `notebooks/analysis.ipynb`: تحليل قابل لإعادة التشغيل.
- `reports/`: التقرير والجداول والرسوم.
- `docs/cleaning_decisions.csv`: سجل قرارات جودة البيانات.
- `.github/skills/`: مهارات مخصصة للمشروع.

## التشغيل
```bash
pip install -r requirements.txt
jupyter notebook notebooks/analysis.ipynb
```

## استخدام الذكاء الاصطناعي
استُخدم مساعد ذكاء اصطناعي للمساعدة في تنظيم خطوات التحليل وصياغة التقرير. يجب مراجعة المخرجات، وتشغيل الدفتر من البداية للنهاية، وعدم اعتماد أي رقم دون الرجوع إلى الجداول الناتجة.

## ملاحظات مهمة
- `test.csv` لا يحتوي على هدف `num_orders`؛ يمكن التنبؤ به لكنه لا يمكن تقييمه دون قيم حقيقية.
- النتائج رصدية، ولا تثبت أن العروض أو الخصومات تسبب زيادة الطلب.
- البيانات الخام مجهولة الهوية لكنها لا تُرفع إلى مستودع عام وفق متطلبات المشروع.


## التنبؤ بالطلب (إضافة تعلّم الآلة)

شغّل من مجلد المشروع الرئيسي:

```bash
python run_ml_analysis.py
```

ينفذ البرنامج تقييمًا زمنيًا على آخر 10 أسابيع معلومة (136–145)، ويقارن نموذج Random Forest بخط أساس يعتمد على طلب الأسبوع السابق. لتناسب سرعة التنفيذ الحواسيب العادية، تُستخدم عينة عشوائية ثابتة تصل إلى 120,000 صف أثناء التقييم و150,000 صف عند تدريب النموذج النهائي.

**نتيجة التقييم الحالي:** MAE نموذج Random Forest = **95.138** طلب، وMAE خط الأساس = **92.939** طلب. التغير في MAE مقارنة بخط الأساس = **-2.37%**؛ والقيمة السالبة تعني أن النموذج لم يتفوق على خط الأساس في هذا الاختبار. لذلك لا ينبغي وصف نموذج الغابة العشوائية بأنه أفضل حاليًا؛ خط الأساس كان أدق على فترة التحقق هذه.

الملفات الناتجة:
- `reports/ml_metrics.json` و`reports/ml_metrics.csv`: نتائج المقارنة.
- `reports/ml_validation_predictions.csv`: القيم الفعلية وتنبؤات النموذج وخط الأساس لأسابيع التحقق.
- `reports/test_predictions.csv`: تنبؤات `num_orders` لصفوف `test.csv`، مع الأعمدة `id` و`num_orders`.
- `reports/ml_feature_importance.csv`: أهمية الميزات وفق النموذج المدرب.
- `reports/figures/ml_mae_comparison.png`: رسم مقارنة MAE.

**تنبيه منهجي:** لا يحتوي `test.csv` على `num_orders` الفعلي، لذا لا يمكن حساب MAE عليه. التقييم العادل تم على أسابيع من بيانات التدريب محجوبة عن النموذج. كما أن بيانات الطلب تاريخية رصدية، والارتباطات لا تثبت السببية.
